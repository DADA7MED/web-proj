# Laptop Store - Contracts & Stores Documentation

This document defines the interface contracts for the shared data layer so every module
(Home page, Product Details, Cart, Admin Panel, Categories, Products) uses **the same source**.

- Stores live in `js/stores/`. Pages must never keep their own copy of products or categories.
- All field names are **snake_case** and match the database: `category_id`, `old_price`, `reviews_count`, `badge_text`, ...
- IDs are **numbers** (the stores convert the API's string ids on load).

---

## 0. How to use the stores (read this first)

```js
import { productsStore } from '../stores/productsStore.js';
import { categoriesStore } from '../stores/categoriesStore.js';

await productsStore.init();   // also loads categories. Required once per page, before any other call.
```

- `await productsStore.init()` loads products **and** categories. A page that only needs categories can call `await categoriesStore.init()`.
- Calling `addProduct / updateProduct / deleteProduct / addCategory / updateCategory / deleteCategory` before `init()` throws an error.
- `init()` can be called many times; it only loads once per page.

### Where data comes from (persistence)

On every page load each store resolves its data in this order:

1. **LocalStorage** - if it already has data, that data is used (so edits survive a refresh).
2. **Database API** (`api/get_products.php`, `api/categoriesApi.php`) - only when LocalStorage is empty. The result is saved to LocalStorage.
3. **Seed data** (`js/data/seedProducts.js`, `js/data/seedCategories.js`) - only when LocalStorage is empty **and** the API is unreachable.

Every add / update / delete is saved to LocalStorage immediately.

| LocalStorage key | Content |
|---|---|
| `laptop_store_products` | `{ version: 2, items: [products] }` |
| `laptop_store_categories` | `{ version: 2, items: [categories and brands] }` (`type` = `category` / `brand`) |

The `version` field protects against stale data: if the browser holds data saved by an older code version
(different shape or no `version`), the store ignores it and reloads from the API. Increase `STORAGE_VERSION`
inside a store whenever its data shape changes.

**Development tip:** after you change data directly in phpMyAdmin, the browser will still show the cached copy.
Either run `localStorage.clear()` in the browser console, or call
`await productsStore.syncFromDatabase()` / `await categoriesStore.syncFromDatabase()` (both overwrite local edits).

## 1. Data shapes

### Product

| Field | Type | Notes |
|---|---|---|
| `id` | number | unique, generated by the store (max id + 1) |
| `category_id` | number | required, must exist in categories |
| `name` | string | required, non-empty |
| `slug` | string | auto-generated and unique if not provided |
| `price` | number | required, `>= 0` |
| `old_price` | number \| null | optional, `>= 0` |
| `rating` | number | default `5` on add |
| `reviews_count` | number | default `0` |
| `stock` | number | `>= 0`, default `10` on add |
| `image` | string | path, e.g. `assets/images/products/apex-14.jpeg` |
| `specs` | object | `{ cpu, ram, storage, gpu }` (any keys allowed) |
| `badge_text`, `description` | string | optional |
| `baseline_price`, `models_count` | number \| null | optional |

### Category (`type: 'category'`)

| Field | Type | Notes |
|---|---|---|
| `id` | number | unique across categories **and** brands |
| `name` | string | required, unique (case-insensitive) |
| `slug` | string | auto-generated and unique |
| `description`, `image`, `badge_text` | string | optional |
| `models_count` | string | display text, e.g. `"34 Models · Sub-3.0 lb"` |
| `baseline_price` | number | `>= 0`, default `0` |
| `features` | string[] | specs chips shown on the card |

Brands (`type: 'brand'`) have the same shape plus `models_list: [{ name, price }]`. They are read-only through `getAllBrands()`.

## 2. Categories Store (`categoriesStore`)

| Method | Returns / behavior |
|---|---|
| `init()` / `fetchCategories()` | Loads data (see section 0). Async. |
| `getAllCategories()` | Array of categories (without brands). |
| `getAllBrands()` | Array of brands. |
| `getAll()` | Categories + brands. |
| `getCategoryById(id)` | Category object or `null`. Accepts number or numeric string. |
| `getCategoryBySlug(slug)` | Category object or `null`. |
| `addCategory(data)` | Validates and adds. Throws if `name` is empty or already exists, or `baseline_price` is negative. Returns the new category. |
| `updateCategory(id, data)` | Partial update. Throws if not found or data is invalid. `id` and `type` cannot be changed. Returns the updated category. |
| `deleteCategory(id)` | Throws if not found, **or if products still belong to the category** (the products store registers a guard). Returns the deleted category. |
| `validateCategoryData(data, isUpdate)` | Throws `Error` with a readable message. |
| `syncFromDatabase()` | Re-fetches from the API and overwrites LocalStorage. |

> The "category still has products" check works whenever `productsStore.js` is imported on the page (always true on Admin).

## 3. Products Store (`productsStore`)

| Method | Returns / behavior |
|---|---|
| `init()` | Loads categories then products (see section 0). Async. |
| `getAllProducts()` | Array of all products. |
| `getProductById(id)` | Product object, or `null` (and a console warning) if not found. Used by Details and Cart. |
| `getProductsByCategory(categoryId)` | Array of products in that category. |
| `addProduct(data)` | Validates and adds. Returns the new product (with generated `id`). |
| `updateProduct(id, data)` | Partial update with the same validation. Throws if not found. |
| `deleteProduct(id)` | Throws if not found. Returns the deleted product. |
| `queryProducts(options)` | Search + filter + sort together (see below). Returns a new array. |
| `validateProductData(data, isUpdate)` | Throws `Error` with a readable message. |
| `syncFromDatabase()` | Re-fetches from the API and overwrites LocalStorage. |

### Validation rules (add and update)

- `name`: required, non-empty string.
- `price`: required, number `>= 0` (0 is allowed).
- `stock`: cannot be negative.
- `old_price`: if provided, `>= 0`.
- `category_id`: required on add, and must exist in `categoriesStore`.
- Missing product on get / update / delete: `getProductById` returns `null`, `updateProduct` and `deleteProduct` throw.

All thrown errors are plain `Error` objects, so wrap calls in `try { ... } catch (e) { show(e.message) }`.

### `queryProducts(options)`

All options are optional and are combined (AND):

| Option | Type | Meaning |
|---|---|---|
| `searchQuery` | string | Every word must match name, description, slug, badge or any value inside `specs` (cpu / ram / gpu / ...). Example: `"rtx 4080"`. |
| `category_id` | number \| null | Only products of this category. |
| `minPrice` / `maxPrice` | number | Price range (inclusive). |
| `inStockOnly` | boolean | Only products with `stock > 0`. |
| `sortBy` | string | `'performance'` (default: most reviews), `'price-low-high'`, `'price-high-low'`, `'rating'`. Applied after search and filters. |

> There is no brand data on products yet, so there is no `brands` filter.

## 4. Pagination component (`js/components/pagination.js`)

```js
const pagination = createPagination({
    container: document.getElementById('pagination'),
    pageSize: 9,
    itemLabel: 'high-performance laptops',
    onPageChange: () => render({ resetPage: false })
});

pagination.setTotal(results.length, { resetPage: true }); // true when filters / search / sort change
const pageItems = pagination.paginate(results);           // items of the current page only
```

- Renders `Showing X–Y of N`, Prev / Next, numbered buttons with `...`, and a "Jump to" box.
- Hides itself when `total` is 0 (the page shows its own "No products found" message).

## 5. Integration notes per module

- **Home page:** `await productsStore.init(); productsStore.queryProducts({ sortBy: 'rating' }).slice(0, 8)`.
- **Product Details:** read `id` from the URL, then `productsStore.getProductById(id)`; handle `null` (show "Product not found").
- **Cart:** use `getProductById(id)` to get `name`, `price`, `old_price`, `image`, `stock` (check `stock` before increasing quantity).
- **Admin Panel:** use `add / update / delete` for products and categories, show `error.message` to the admin, and re-render from `getAll...()`.
- **Products page links from Categories:** `products.php?category=<slug>` and `products.php?search=<text>` are read by `js/pages/products.js`.
